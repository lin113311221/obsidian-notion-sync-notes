# B站：接口直连更稳，但 AI 字幕要登录态

跟小红书相反 —— B站的收藏夹**有稳定的公开接口**，不需要走 webview。
但也有它自己的坑。

---

## 登录：SESSDATA

B站的凭证就是一个 Cookie 字段 `SESSDATA`。

获取方式（让用户自己做）：
浏览器打开 bilibili.com 并登录 → F12 → Application/存储 → Cookies → 复制 `SESSDATA`

**在插件设置页里做一键提取**，比让用户手动复制粘贴体验好得多：
内嵌 webview 打开 B站，登录后从 session 里读 `SESSDATA`。

---

## 坑 1：AI 字幕必须带登录态

这是最容易踩的一个，因为**症状具有误导性**。

匿名调字幕列表接口：

```
GET /x/player/v2?bvid=...
→ 返回成功（HTTP 200），但 subtitle 列表是空的
```

**不是报错，是空数组。** 你会以为"这个视频没字幕"，实际上是你没登录。

带 `SESSDATA` 再调同一个接口，AI 字幕就出现了。

> 我们三方证实过这个行为。结论：**没登录时不要下"该视频无字幕"的判断**，
> 否则用户会看到大量"本视频无字幕"的错误结论。

### 字幕接口的两个来源

- **UP 主上传的字幕**（CC 字幕）—— 匿名也可能拿到
- **AI 字幕**（平台自动生成的）—— 必须登录态

两者在同一个 `subtitle` 字段里，靠 `lan` / `lan_doc` 区分。

---

## 坑 2：搜索接口已经要 wbi 签名了

```
GET /x/web-interface/search/type?...
→ 匿名直接返回风控 HTML（不是 JSON）
```

**不要试图在插件里做全站搜索。** 两个理由：

1. 要算 wbi 签名，而算签名的 key 会轮换（跟小红书的 `x-s` 同构，是个无底洞）
2. 同步工具根本不需要搜索 —— 用户要的是"我的收藏"，不是"全站内容"

需要搜索功能时，考虑让用户在 B站 里搜完再收藏，我们只同步收藏夹。
**边界画清楚，能省掉一整类维护负担。**

---

## 收藏夹列表接口

带 `SESSDATA` 直接调，返回结构稳定。几个注意点：

- 分页用 `pn` / `ps`，`ps` 上限 20 左右，别贪心设大
- 响应里 `code !== 0` 要处理（`-101` 是"账号未登录"）
- 收藏夹可能有多级（默认收藏夹 + 自建收藏夹），要分别拉

### 逐个详情 vs 列表已够

列表接口通常已经带标题、UP 主、封面、时长。
**只在用户勾选"要逐字稿"时才去拉详情** —— 详情接口慢得多，全量拉会很卡。

这是一个通用的优化思路：**把最贵的接口变成可选项，默认关闭。**

---

## 和小红书方案的对比

| | B站 | 小红书 |
|---|---|---|
| 取数方式 | 接口直连 | 内嵌 webview + 响应拦截 |
| 凭证 | SESSDATA（一个 Cookie） | 整站 Cookie |
| 稳定性 | 高，接口长期稳定 | 中，依赖 DOM 结构 |
| 维护成本 | 低 | 中（改版要更新选择器） |

**结论：能直连就直连，别一上来就上浏览器方案。**
webview 那套是"没有稳定接口时的退路"，不是默认选择。
